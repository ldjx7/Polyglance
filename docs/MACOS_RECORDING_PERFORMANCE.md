# macOS 录屏合成优化

## 调整范围

macOS 已使用 ScreenCaptureKit 采集、独立队列写入 H.264、AVPlayer 播放。本次保留这些流程，优化同时录制系统声音和麦克风后的合成。

旧流程将视频和两路音频加入同一个 composition，再用 HighestQuality 导出整段 MP4。新流程分两步：

1. 仅将音轨加入 composition，使用 AppleM4A 预设混音。
2. 将原始视频和混好的音频用 Passthrough 预设合并到 MP4。

音轨按原时间位置插入，保留麦克风晚开始、提前结束的情况；视频保留画面方向。只有整个流程成功后才替换原文件，取消或失败会清理中间文件。仅有一条实际音轨时直接返回原文件。

接口依据：[AppleM4A](https://developer.apple.com/documentation/avfoundation/avassetexportpresetapplem4a)、[Passthrough](https://developer.apple.com/documentation/avfoundation/avassetexportpresetpassthrough)。视频是否保持原样还通过压缩数据与时间戳比较验证，不只依赖预设名称。

## 合成耗时对比

2026-09-23，在 Apple M2 Pro、macOS 27.2 上测试。基线为 `0066d00` 中的合成实现。

素材由 FFmpeg 生成：10 秒、1920×1080、60 fps H.264 动态测试画面，附两条 48 kHz AAC 音轨。对同一输入文件的新副本运行新旧流程各三次，交替执行顺序；计时覆盖混音、导出、替换文件，不包含生成素材或复制输入。

| 流程 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 旧流程 | 3.440 秒 | 3.115 秒 | 3.194 秒 | 3.194 秒 |
| 新流程 | 0.252 秒 | 0.215 秒 | 0.240 秒 | 0.240 秒 |

该样本合成耗时减少约 92.5%。三份新输出的 600 个视频压缩数据包及 PTS、DTS、持续时间均与输入一致，FFmpeg 完整解码通过。

这是合成阶段的合成素材测试，不代表所有设备、时长或真实录屏场景都获得相同提升，也不用于证明采集阶段没有丢帧。新流程仍需遍历音频和复制视频数据，长录屏仍会受存储速度影响。

复现：

```sh
./scripts/benchmarks/macos-recording/run.sh 0066d00
```

需要 macOS Swift 工具链、FFmpeg 和 Python 3。脚本直接编译当前生产合成模块，选用的历史实现仅作为对照；临时目录保留输出文件和耗时记录。

## 回归验证

新增原生 AVFoundation 集成测试，不依赖 FFmpeg：

- 比较视频压缩数据、帧时间戳、帧间间隔和画面方向。
- 检查两路不同频率的声音均进入最终单条音轨，麦克风不会提前发声，提前结束的音频不会延长。
- 实际只有一条音轨时文件字节保持不变。
- 取消时原录制文件保持不变，中间文件得到清理。

已有音频混合测试继续保留。测试入口：

```sh
swift test --package-path apps/macos
```

本次完整验证：macOS 565 项测试通过，开发应用构建及严格签名验证通过；真实 Windows 构建机 296 项测试通过，应用、安装包和便携 ZIP 均已生成，安装包目录仅保留本次两个产物，没有遗留应用进程。macOS 14 的兼容导出分支保留，运行测试使用上述当前系统，未在 macOS 14 实机上测试。
