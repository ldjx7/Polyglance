# 截图与贴图历史审查修复方案

## 执行范围

基于现有未提交的历史功能实现修复，保留其他已完成的截图、焦点、权限、设置及翻译逻辑。先完整阅读 AGENTS.md 和 PIN_HISTORY_IMPLEMENTATION_PLAN.md。本文件补充并修正原方案；发生冲突时以本文件为准。

用户已要求直接实施，无需再次请求开工确认。不得提交、推送、创建 tag 或安装应用。不得输出凭据。不得清空用户真实历史来测试。

## 1. 真正的缩略图与后台读取（优先）

现状：Windows PinHistoryWindow.RefreshItems 在界面线程对所有记录调用 LoadImage 完整解码；macOS PinHistoryViewModel 缓存 NSImage 原图。PNG 磁盘容量限制不能限制解码后的内存。

- 存储层区分 loadThumbnail 与 loadImage，历史列表只能调用前者。
- 使用平台原生解码降采样，缩略图最长边最多 480 像素；禁止先完整解码大图再缩小。macOS 可用 ImageIO 缩略图解码；Windows 使用 WPF 解码尺寸参数，处理长宽方向及宽高比。
- 在后台读取和生成缩略图，限制并发（建议 2），只在主线程发布界面状态。Windows 跨线程 BitmapSource 必须 Freeze；macOS 避免后台调用要求主线程的 AppKit 绘制接口。
- 加载采用代次标识或取消机制，刷新、删除、清空后不得被旧任务重新填入记录。缓存设置实际内存预算（建议 32 MiB），关闭或隐藏窗口时释放不必要缓存。
- PNG 编码与持久写入也应避免长时间占用界面线程，同时通过同一串行存储队列保证写入、删除、清空顺序。清空前排队的写入不得在清空后重新出现。
- 仅再次贴出所选图片时读取原图；展示加载状态和可理解的失败提示，不阻塞已有贴图显示。

## 2. Windows DPI 和目标屏幕定位

现状：PinHistoryWindow.PinItem 和 App.RestoreMostRecentPin 混合物理像素与 WPF DIP；PinWindow 构造函数仍按主屏工作区限制尺寸。

- 提取共享定位计算，供两个历史入口复用。
- 明确所有坐标的单位，正确转换鼠标、目标屏幕工作区和 WPF 窗口坐标，不能对整个虚拟桌面套用单一主屏缩放率。
- 按鼠标所在屏幕的可用区域约束图片和整个窗口尺寸，计入边框、内边距及可见控件。无截图逻辑尺寸的历史图片按该区域等比缩小。
- 在目标屏幕 DPI 已确定的正确生命周期中应用位置，必要时使用现有原生窗口定位工具。沿用现有截图显示尺寸规则，不能回归普通截图贴图。
- 测试 100%、125%、150%、200%，负坐标副屏、左右上下排列、不同缩放混合以及副屏小于主屏。无实体双屏时做几何测试并明确人工验证范围。

## 3. 损坏索引恢复、文件校验及容量统计

- macOS 索引缺失或损坏时，不可直接把现有图片视为空历史。备份损坏索引，然后扫描档案自身的 pin_*.png，重建有效记录并原子保存索引。
- 两端都校验记录结构、唯一 ID、文件名、尺寸及图片可解码性；非空文件不代表有效图片。单项损坏不能丢弃全部有效记录或使列表崩溃。
- 文件名只能是当前档案目录内的合法图片文件名，拒绝绝对路径、父目录跳转和逃逸目录的符号链接，避免删除或清理越界。
- 能恢复的元数据保留；无法恢复来源时标记 legacy，并取合理文件时间。排序稳定，相同时间保持明确的次序。
- 坏图片应从有效索引移除，保留可诊断的隔离状态，不能每次扫描重新导入；不得自动删除目录外文件。
- 明确定义档案内孤立 PNG、临时文件、隔离文件的管理与容量策略，避免索引损坏后长期积累不计入限制的文件。备份限制数量，不无限增长。
- 恢复、迁移必须幂等；避免在每次普通列表读取中重复全量解码校验，可缓存有效的文件指纹。

## 4. 删除与写入失败不能伪装成成功

- append/delete/deleteAll 返回结构化结果，区分成功、部分失败和失败；保留日志，不记录图片内容或凭据。
- 文件删除失败时保留可管理记录并提示；清空部分失败时保留失败项，报告数量和可重试操作，不能显示已全部清空。
- PNG 写入成功而索引失败，必须回滚新文件或进入明确可恢复流程；不能向调用者返回已持久保存成功。
- 文件删除成功而索引失败时，下次加载应移除缺失记录；索引失败要向界面反馈。
- 容量清理同样处理文件删除失败，不能仅减去账面容量却留下实际文件，也不能为清理失败不断删除更多正常图片。
- 针对 Windows 文件占用、拒绝访问以及索引写入失败进行测试。macOS 的会话级关闭恢复栈与磁盘档案保持独立；界面说明删除磁盘历史不关闭当前贴图、不清理会话撤销栈。

## 5. 修正文档的截图历史范围

原方案只保存已贴出的图片，无法覆盖普通截图复制和保存后的历史需求。为避免默认把更多敏感截图写入磁盘，采用显式设置：

- 两端设置增加保存已完成截图到历史开关，默认关闭并兼容旧配置，旁注明只保存在本机、最多 30 条/512 MiB，可随时清空。
- 现有已贴出图片的历史行为继续保留。开关只控制额外的普通截图和长截图复制/另存为成功后的保存；不能因为开关关闭而破坏已有贴图历史。
- 开启后，成功复制或保存的最终图片（包括已合成的标注）进入现有档案，来源保持 screenshot/longScreenshot；保存对话框取消、复制失败、取消截图、二维码识别不记录。
- 同一次完成事件只记录一次；从历史再次贴出永远不追加。同图的独立截图操作可以各自保留，不做跨操作全局去重。
- 不主动监听或保存其他应用的剪贴板内容。不在用户开启设置之前追溯采集。
- 历史界面说明截图自动记录开关的状态及入口，明确翻译历史保存的是原图还是已合成图片；保留原地翻译当前功能，不擅自改变输出内容。
- 更新原方案的范围和验收标准。文档中的修复前分析标为修复前状态，不再与完成后的行为混写。

## 6. 回归测试与验收

先补能暴露问题的失败测试，再修复：

1. 大尺寸、长宽比例极端的图片生成受限缩略图；列表不调用原图加载；刷新取消、缓存预算、关闭释放。
2. 双历史入口共用定位逻辑；不同 DPI、负坐标及小副屏测试。
3. 先写入至少两张有效图片，再破坏或删除索引，验证重建后图片仍可浏览和贴出。
4. 非空损坏 PNG、截断图片、无效记录和未知来源不影响正常项；索引重建和旧文件迁移重复执行不重复导入。
5. 删除、清空、容量清理及索引写入失败，验证界面反馈与磁盘状态一致；失败记录仍可管理。
6. 新开关默认值、旧配置读取、保存成功、保存取消、复制失败、长截图及标注结果、事件防重复。
7. 从历史贴出不新增记录；macOS 最近关闭恢复及现有焦点、窗口拉伸、菜单、翻译行为无回归。
8. 测试一律注入临时档案，检查既有 PinWindowManager/PinWindow 测试也不会向用户真实档案写入或触发清理。
