# 长截图问题分析与修复建议

## 1. 分析范围与结论

| 项目 | 内容 |
| --- | --- |
| 分析日期 | 2026-10-04，北京时间 |
| 分析对象 | Windows Rust + Slint 重构分支 `refactor/windows-rust-track` |
| 源码版本 | `e08446c5a2b5e6aeda96ded1f8b35568f970500b` |
| 文档存放分支 | 剪贴板功能分支 `feat/clipboard-history` |
| 验证范围 | 源码调用链、控件布局计算、共享拼接模块单元测试 |
| 尚未验证 | Windows 真机交互、真实页面兼容性、性能和内存峰值 |

共享 Rust 拼接算法已经具备上下双向拼接、重复内容处理、固定区域识别和资源限制等能力，但 Windows 的采集会话、交互与导出尚未完整衔接。最严重的问题是已经生成的长图会在导出前被普通截图覆盖。

本文记录五项问题及后续修复方案，所有问题均尚未修复。文档存放在剪贴板分支，分析对象仍是上述 Windows 重构版本；本文没有合并该分支，也不代表 macOS 或旧 C# 客户端存在相同问题。

下方源码链接固定到被分析的提交，避免后续分支变化导致分析依据不一致。

## 2. 当前实现结构

### 2.1 相关模块

| 模块 | 当前职责 | 源码 |
| --- | --- | --- |
| Win32 截图浮层 | 选区、进入长截图、定时采集、缩略图、完成和取消 | [win32_overlay.rs][overlay] |
| 桌面主程序 | 托盘入口、独立后台采集、复制、贴图和 PNG 保存 | [main.rs][main] |

| 公共 Rust 拼接核心 | 接收 RGBA 帧、估计位移、合并图像、生成预览、限制资源 | [stitch.rs][stitch] |
| Slint 托盘和主窗口 | 托盘菜单、长截图回调、状态显示 | [app_window.slint][ui] |

整体客户端使用 Rust + Slint，长截图浮层实际由 Rust 调用 Win32 绘制和处理消息。

### 2.2 两套入口并存

| 项目 | 普通截图工具栏进入长截图 | 托盘菜单直接进入长截图 |
| --- | --- | --- |
| 入口 | 浮层长截图按钮，将状态切为 `LongCapturing` | `on_long_capture_clicked()` → `run_long_capture()` |
| 选区 | 继续使用当前截图选区 | 调用 `select_screen_region_rect()`，内部打开完整截图浮层 |
| 采集 | `WM_TIMER`，请求间隔 33ms；实际频率受处理耗时影响 | 后台循环最多 600 轮，每轮处理后等待 500ms |
| 滚动 | 用户手动滚动底层页面 | 用户手动滚动底层页面 |
| 捕获范围 | 当前选区四边各向内缩 2 像素 | 返回选区的完整矩形 |
| 预览 | 最多 120×240 像素的缩略图 | 外层后台采集没有同样的实时预览 |
| 结束 | 复制、贴图、保存；取消返回普通选区状态 | 再次点击托盘长截图设置停止标记，或达到循环次数、资源限制 |
| 保存目录 | `%USERPROFILE%/Pictures/Polyglance` | `%APPDATA%/Polyglance/LongScreenshots` |

这里描述的是当前代码路径。浮层导出存在问题一，托盘入口存在问题二，不能把表中的导出能力视为已通过端到端验收。

### 2.3 共享拼接算法

`Stitcher` 的处理顺序：

1. 接收首帧，建立输出图像并记住上一帧。
2. 新帧完全相同时，返回 `Unchanged`。
3. 在允许的正、负位移范围内粗筛候选，再对候选进行更密集的像素采样比较；上一帧位移参与预测。
4. 尝试识别固定表头、页脚和侧边栏，减少固定区域对匹配和拼接的影响。
5. 位移可信时，只追加或前插尚未捕获的内容；滚回已有区域时通常不增加输出长度。
6. 匹配不可靠时返回 `NoReliableVerticalOverlap`，保留上一张已接受帧，供后续匹配使用。
7. 按输出尺寸、像素量和估算工作内存限制图像增长，保留已经得到的结果。

默认配置包括：单边最大 32,768 像素、最大 80,000,000 像素、384 MiB 估算工作内存预算，以及最多 10,000 个计入拼接的帧。384 MiB 是核心的预算估算，不等于整个应用的进程内存上限。

核心提供横向拼接和裁边接口，但 Windows 两个入口目前均固定为纵向，未接入这些交互。自动滚动、暂停恢复和页面到底后的自动结束也尚未实现。

被分析版本的 `stitch.rs` 与剪贴板分支提交 `06c146b1ed4a8517083dd61bfdceab0e2b3a19d8` 中的文件完全一致，可以继续共用，无需另外复制一套 Windows 拼接算法。

## 3. 问题清单

优先级含义：P1 表示直接影响主要功能结果或完成操作；P2 表示影响恢复、反馈或性能，需要在完整验收前处理。

| 编号 | 优先级 | 问题 | 确认程度 |
| --- | --- | --- | --- |
| 1 | P1 | 导出前用普通截图覆盖拼接结果 | 已确认无条件覆盖的调用链，待 Windows 实机复现 |
| 2 | P1 | 托盘入口与浮层入口重复采集、行为不一致 | 已确认调用链丢弃动作和图像，待 Windows 实机复现 |
| 3 | P1 | 大选区使控制栏落入被挖掉的窗口区域 | 已确认布局计算结果，待 Windows 实机复现 |
| 4 | P2 | 失败被忽略、达到上限后仍继续采集 | 已确认错误分支和定时器处理，待 Windows 实机复现 |
| 5 | P2 | 浮层消息线程同步执行采集与拼接 | 已确认执行结构，卡顿程度需实测 |

### 3.1 问题一：导出覆盖拼接结果

**触发条件与影响**

从普通截图工具栏进入长截图，滚动后点击复制、贴图或保存。即使缩略图已经显示长图，最终传给复制、贴图和保存流程的仍可能是最初一屏的普通截图。

**代码依据**

- [长截图完成按钮处理][finish-buttons]：先调用 `long_stitcher.take()` 和 `render()`，把长图写入 `selected_image`。
- 随后进入公共 `handle_action()`。
- [`handle_action()`][handle-action]：在读取初始桌面截图 DC 后，无条件调用 `capture_annotated_selection()`，重新赋值 `selected_image`，覆盖前一步生成的长图。
- `main.rs` 的复制、贴图、保存分支随后使用 `sel.image`，因此收到被覆盖的结果。

**修复建议**

让完成操作显式接收会话生成的图像。普通截图需要生成标注图，长截图应直接交付拼接结果；长截图渲染失败时应提示错误并保留会话，避免退回普通单屏图像后报告成功。

**验收要求**

- 分别验证复制、贴图、保存，输出高度均大于原始选区高度，并包含滚动后新增内容。
- 补充会话结果传递测试，验证完成处理不会覆盖传入的拼接图像。
- 首帧尚未成功或渲染失败时，不应导出普通截图冒充长图。

### 3.2 问题二：托盘入口重复启动采集

**触发条件与影响**

从托盘点击长截图后，会进入完整截图浮层。如果用户又在这个浮层中点击长截图并完成，外层仍会拿着选区重新开始后台采集。浮层中的复制、保存或贴图动作，以及已生成图像，都不会作为此次托盘任务的最终结果使用。

另外，外层提示用户点击停止按钮，但主窗口在启动时被隐藏，界面没有对应的独立停止按钮；再次点击托盘中的长截图菜单可以设置停止标记，但菜单标题仍固定为长截图，缺少明确提示。

**代码依据**

- [`run_long_capture()`][background-capture] 先调用 `select_screen_region_rect()`，随后新建 `Stitcher` 并开始自己的采集循环。
- [`select_screen_region_rect()`][select-rect] 调用完整 `select_screen_region()` 后仅返回 `s.rect`，丢弃 `action` 和 `image`。
- [`on_long_capture_clicked()`][tray-session] 使用 `is_long_capturing` 和原子停止标记管理外层任务，与浮层的 `LongCapturing` 状态相互独立。
- 两条路径的采样间隔、捕获边界、预览、完成行为及保存目录都不同。

**修复建议**

托盘和截图工具栏都进入同一个长截图会话。托盘路径只增加前置选区步骤；选区确认后自动进入长截图。选区接口明确区分只选区域和完整截图编辑，避免把一次已经完成的操作当成新任务的选区输入。

**验收要求**

- 两个入口各只创建一个会话和一个采集循环。
- 点击完成后只导出一次，不再次进入后台采集。
- 点击取消后不保存，也不重新启动会话。
- 所有入口都能看到可操作的完成、取消和当前状态；退出应用时停止后台任务。

### 3.3 问题三：大选区裁掉控制栏

**触发条件与影响**

选区覆盖大部分屏幕或到达屏幕底部时，工具栏可能被移动到选区内部。进入长截图后，选区内部又被从窗口区域中移除，导致复制、保存、贴图和取消按钮不可见、不可点击。状态栏和预览也存在相同布局风险。

**代码依据与计算示例**

- [进入长截图时的窗口区域设置][enter-long] 使用 `SetWindowRgn()` 从整个浮层中减去选区内部区域，以便操作底层页面。
- [控制栏布局函数][long-layout] 仅按屏幕边界夹取位置，没有确保控件位于挖空区域之外。
- 对于 1920×1080 的整屏选区，挖空区域为 `(2, 2)` 到 `(1918, 1078)`；工具栏会落在 `(870, 1028)` 到 `(1050, 1068)`，完全处于被移除的区域内。这是布局计算结果，尚未进行 Windows 画面验证。

**修复建议**

将控制面板作为独立窗口管理，并根据当前显示器的可用空间布置。若面板必须覆盖捕获区域，应明确处理捕获排除或采集时隐藏，避免把面板拼入长图。选区边框、鼠标穿透和控制面板不能共用简单的整块挖空规则。

**验收要求**

- 验证整屏、贴边、大选区、小选区，以及负坐标副屏和跨屏选区。
- 各场景下完成、取消按钮都可见且可点击。
- 缩略图、状态提示和控制面板不会进入捕获结果。

### 3.4 问题四：错误与资源上限没有形成明确状态

**触发条件与影响**

- 捕获失败或拼接报错时，界面继续保留正常滚动提示，没有告诉用户哪些内容未被记录。
- 滚动太快、相邻画面缺乏足够重叠时，当前帧被拒绝。由于核心仍保留上一次接受帧，后续继续向前滚动可能持续匹配失败；没有返回可匹配位置或结束保存的引导。
- 达到资源上限后，浮层只更改提示文字，没有停止采集定时器。之后出现 `Unchanged` 帧时，正常提示还可能覆盖上限提示。

**代码依据**

[`WM_TIMER` 的长截图处理][timer] 中，捕获失败没有错误分支；`NoReliableVerticalOverlap` 和其他拼接错误均被忽略。`limit_reached` 只影响文字，没有调用 `KillTimer()` 或切换到停止采集状态。

**修复建议**

增加明确的采集、等待恢复、达到限制、正在导出、已完成、已取消和失败状态。偶发匹配失败可以容忍；连续失败应提示放慢滚动、返回上一可匹配位置，或保存已有内容。达到资源上限后停止采集，并保留预览和导出操作。状态变化应区分匹配失败、没有新增内容和资源限制。

**验收要求**

- 注入捕获错误、连续匹配失败和尺寸变化，确认有可理解的提示与可执行操作。
- 达到尺寸、像素、内存或帧数限制后，不再采集；已有结果仍能导出。
- 上限或错误状态不会被下一帧正常状态文字覆盖。
- 停止、取消和重新开始时，不会接收上一会话的迟到结果。

### 3.5 问题五：同步计算可能影响交互响应

**触发条件与影响**

大分辨率选区、多显示器或长时间滚动时，捕获和拼接开销增加，可能使浮层按钮、鼠标反馈及重绘延迟。当前尚无 Windows 真机性能数据，不能据此断言已经发生卡顿或承诺帧率。

**代码依据**

- [`WM_TIMER`][timer] 在浮层窗口消息线程内持有状态锁，同步执行 GDI 捕获、BGRA 转 RGBA、拼接和缩略图生成。
- 每个成功返回的帧都会更新预览并触发重绘，包括 `Unchanged`。
- [`paint_overlay()`][paint] 每次绘制都创建覆盖虚拟桌面的兼容位图和 DC，并绘制浮层。
- 33ms 是请求的定时器间隔，不是实际采集或渲染达到 30 FPS 的证明。

**修复建议**

将捕获和拼接安排到串行后台工作任务，窗口线程只处理输入与轻量更新。确保只有一个任务推进拼接状态，并限制待处理帧数量，避免任务积压和内存增长；预览仅在内容或状态变化时更新，绘制缓冲区按尺寸变化复用。调度策略要兼顾重叠需求，不能通过无界排队或持续丢帧维持表面流畅。

**验收要求**

- 在常见分辨率和 4K 场景记录采集、拼接、预览、按钮响应耗时，以及 CPU、内存峰值。
- 长时间滚动后待处理任务数量有界，完成和取消保持可响应。
- 停止或取消后不再继续捕获、提交预览或写入结果。

## 4. 建议的修复顺序和模块划分

1. 优先修复问题一，确保已经拼出的结果能够正确交付，并补结果传递测试。
2. 统一托盘与工具栏入口，抽出一个 `LongCaptureSession` 管理会话，解决问题二。
3. 调整控制面板和选区的窗口关系，解决问题三。
4. 增加错误恢复、资源上限、完成与取消状态，解决问题四。
5. 将采集和拼接移到有界的串行后台任务，结合性能数据解决问题五。
6. 完成基本流程和真机验收后，再增加自动滚动、暂停恢复、横向入口和后续编辑能力。

| 层次 | 建议职责 |
| --- | --- |
| 公共 Rust `Stitcher` | 保留像素匹配、位移判断、拼接、预览和资源预算 |
| 公共 Rust `LongCaptureSession` | 管理会话状态、帧接受结果、连续失败、达到上限、取消与最终图像；使用会话标识丢弃迟到结果 |
| Windows 平台适配 | 屏幕捕获、窗口和显示器坐标、线程调度、控制面板、复制和保存 |
| 各入口 | 收集选区并启动同一会话，不再维护第二套长截图循环 |

此次文档变更只记录方案，未修改公共 Rust、macOS、Windows Rust 或旧 C# 实现。后续修复若涉及共享核心，需要验证其他平台调用方；Windows 专属交互修改应在重构分支实施。
