# PixPin 功能对照与实施路线

## 1. 目的与范围

本文档用于指导 Polyglance 的 macOS 截图、标注与贴图能力建设。目标不是逐项复制 PixPin，而是参考其已经验证过的基础交互，优先形成一条稳定、连贯、适合翻译工具的工作流：

```text
触发截图 → 智能/自由选区 → 精调与标注 → 复制 / 保存 / 贴图 / OCR 翻译
```

PixPin 的会员服务、账号体系、云端表格/公式识别不属于当前项目的对标范围；Windows 独占的托盘和命令行行为也不直接移植到 macOS。

## 2. 调研依据

本次梳理同时参考了 PixPin 官方文档和本机 macOS 版偏好设置。官方资料用于确认产品能力，本机检查用于确认 macOS 确实暴露了对应配置；由于自动化环境无法触发 PixPin 的全局截图快捷键，本机运行态截图浮层、贴图菜单和长截图过程没有被视为已实测行为。

## 3. PixPin 功能地图

本节同时包含 PixPin 的免费与会员能力，只用于理解产品边界和交互设计，不代表本项目会复刻其商业分层。具体能力归属以 PixPin 的[会员功能说明](https://pixpin.cn/docs/start/pro-features)为准。

### 3.1 静态截图

- 区域、窗口、细粒度 UI 元素识别。
- 鼠标拖动自由框选，单击确认候选，双击复制截图到剪贴板。
- 点击选区外按八方向扩大选区。
- 八方向控制点、移动、固定比例和手动尺寸。
- 方向键像素级移动，组合键收缩或扩大边界。
- 放大镜、网格、十字线、坐标、RGB/HEX 等取色信息。
- 是否包含鼠标、圆角、阴影、边框和历史区域。
- 复制、保存、快速保存、贴图、OCR 等结果动作。

### 3.2 标注

- 画笔、荧光笔、直线/折线、箭头、矩形、椭圆、序号和文字。
- 马赛克、模糊、智能擦除、橡皮擦、聚光灯、水印和放大镜；其中智能擦除等部分能力属于会员功能。
- 颜色、透明度、粗细、字体和填充样式。
- 撤销、重做、清空、选中后二次编辑与删除。
- 截图与贴图可分别记忆上次使用的工具。

### 3.3 贴图

- 来源包括截图、剪贴板、文件、文本/HTML、颜色和 LaTeX。
- 拖动移动、滚轮缩放、细粒度缩放、透明度和中键重置。
- 锁定、切换置顶、鼠标穿透、跨桌面显示、临时隐藏。
- 复制、保存、裁切、再次标注、旋转、翻转和基本图像处理。
- OCR 文字选择、二维码识别、翻译；翻译属于会员或自备 API 能力。
- 缩略图、标题、分组、批量操作、历史恢复与会话恢复。

### 3.4 OCR 与翻译

- 截图 OCR，以及贴图中的本地 OCR 文字选择、复制和拖出。
- 二维码识别。
- OCR 文本翻译和图片翻译，属于会员或自备 API 能力。
- 表格、公式和工业条码属于 PixPin 的高级/会员能力，不作为本项目首批目标。

### 3.5 长截图与录屏

- 纵向或横向滚动拼接、实时预览、端部裁剪和中间区块删除。
- 普通录制输出 MP4/GIF/WebP，快速录制输出 MP4。
- 帧率、延时、暂停、麦克风/系统音频和录制中标注。
- 摄像头画中画、键鼠展示和剪辑属于 PixPin 会员能力，也是本项目的更后期能力。

### 3.6 动作与配置体系

- 全局快捷键、局部快捷键、鼠标绑定和托盘动作均可配置。
- 截图、复制、保存、贴图、OCR、历史恢复、隐藏/显示贴图等能力被建模为独立动作。
- 对本项目的设计启发：把能力建模为独立动作，允许用户组合主流程，而不是为每种流程维护一套独立界面。

## 5. 分阶段实施

### Phase A：基础交互闭环

实现状态：代码和自动化测试已完成，等待真实多屏、鼠标和窄屏环境人工验收。

- 截图直接保存。
- 按真实输出像素移动、扩边和收边。
- 标注元素基础模型。
- 画笔、矩形、椭圆、箭头。
- 撤销、重做。
- 贴图以鼠标为锚点的滚轮缩放。
- Option + 滚轮精细缩放，Command + 滚轮调整透明度。
- 贴图锁定、切换置顶、中键恢复初始尺寸。

验收标准：既有选区、右键、Esc、多屏、复制、贴图行为不回归；预览和输出标注一致；所有新增状态有自动化测试。

### Phase B：翻译工具的差异化能力

实现状态：基础版已完成；标注样式、二次编辑和普通贴图内 OCR 仍待实现。

- 使用 Vision 做离线 OCR。
- 截图工具栏增加“复制文字”和“OCR 翻译”。
- 截图 OCR 结果允许在原图上连续选择、复制或拖出字符；空闲时不绘制识别框，选中后才显示轻量快捷动作，并提供选中/全文分离快捷键、退出选择但保留贴图和 Option 拖动；普通图片贴图内再次进入 OCR 待实现。
- OCR 翻译直接生成邻近截图选区的原文+译文结果卡，可切换原图/OCR 原文/译文、复制当前文字态，并接入普通图片贴图共用的批量操作和关闭历史。
- 放大镜、坐标和 RGB/HEX 取色。
- 文字、马赛克、样式选择和标注二次编辑。

验收标准：OCR 本身不上传图片；只有用户执行翻译时，识别后的文本才发送给当前配置的翻译服务。

### Phase C：效率与恢复能力

- 截图与选区历史、重复上次区域、延时截图。
- 普通图片与 OCR 翻译贴图的隐藏/显示/关闭/销毁全部和进程内历史恢复已统一；鼠标穿透和应用重启恢复待实现。
- 贴图裁切、旋转、翻转、缩略图。
- 更完整的全局动作和自定义快捷键。

### Phase D：独立大型能力

实现状态：纵向/横向手动滚动长截图和区域 MP4/GIF 普通录制基础版已完成；录屏已支持可编辑蓝框准备、0/3/5 秒倒计时、5/16/24/30/60 FPS（GIF 限 5/16）、红框录制/橙框暂停、同快捷键控制、停止后回放，以及三档质量、默认格式/保存目录/保存询问策略、鼠标指针和 MP4 音轨选项。

- 纵向上下双向、横向左右双向的手动滚动长截图已完成；自动滚动、端部裁剪和中间区块删除待实现。
- 区域 MP4 录屏和系统声音/麦克风已完成；GIF 无声短录制已完成。回放可保存、静默快存、复制文件和重新录制；录制中关闭、未保存回放关闭/重录、应用退出都会先提供保存/丢弃/取消，普通保存覆盖采用同目录临时文件原子替换。时间轴剪辑、速度调整、快速录制模式、MOV/WebM/APNG/WebP、摄像头、键鼠展示和录制中标注待后续评估。
- 二维码识别。
- 贴图分组和跨桌面工作区。

## 6. 架构约束

1. 截图、窗口、权限、Vision OCR、鼠标键盘事件和贴图都属于 Swift/AppKit 平台层。
2. Rust 继续负责翻译请求、服务适配、缓存、可跨平台的业务历史和平台无关数据处理；与 AppKit 窗口状态绑定的贴图恢复快照仍位于 Swift 平台层。
3. 长截图的拼接算法、图像编码等纯计算模块未来可以下沉 Rust；捕获、滚动区域识别和权限仍在 Swift。
4. 标注先使用 Swift 的模型与渲染，等 Windows 端启动后再评估是否把纯几何和序列化格式共享到 Rust，避免过早抽象。
5. 每个用户动作应有明确状态、可取消路径和错误反馈；不能用静默 `try?` 隐藏保存或剪贴板失败。

## 7. 录屏格式路线

| 格式 | 当前决策 | 适用场景 | 实现备注 |
| --- | --- | --- | --- |
| MP4 (H.264/AAC) | 已实现，默认 | 通用分享、长录制、需要系统声音或麦克风 | 三档帧率/分辨率/码率，兼容性优先 |
| GIF | 已实现 | 短小、静音的操作演示 | 8/12/15 FPS，限制最长边、时长、帧数和临时空间 |
| MOV | 推荐下一阶段按需增加 | macOS 剪辑、高质量中间文件、未来 HEVC/ProRes | 可继续复用 AVFoundation；会显著增加编码选项和测试矩阵 |
| WebM | 后续评估 | Web 发布、开放容器 | 系统原生编码链路不足，通常需要引入并维护第三方编码器 |
| APNG | 后续评估 | 需要透明度或更好色彩的短 UI 动画 | 仍然无音轨；需验证 Image I/O 动画写入和目标平台兼容性 |
| Animated WebP | 暂缓 | 更小的网页动画 | 当前机器的 Image I/O 写入类型不含 WebP，需要第三方实现 |

不建议第一版同时加入全部格式。当前 MP4 覆盖“视频+声音”，GIF 覆盖“短静音演示”；只有出现明确的剪辑、透明动画或 Web 体积需求时，再分别引入 MOV、APNG 或 WebM/WebP。

## 8. 不直接照搬的部分

- 不复制 PixPin 的名称、图标、视觉素材和会员体系。
- 长截图与录屏保持独立子系统和可取消状态机，不与普通截图、历史数据库或完整标注编辑器耦合。
- macOS 使用 Command 作为常用修饰键，并尊重系统桌面/窗口行为，不机械照搬 Windows 快捷键。
- OCR 优先使用系统 Vision；翻译仍复用现有 Rust 内核，保持跨平台业务一致性。
