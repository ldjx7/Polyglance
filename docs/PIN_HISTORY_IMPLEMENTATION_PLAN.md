# Polyglance 贴图历史方案

更新说明：本文保留最初的图片历史设计背景。当前图片／文本贴图的关闭、销毁和重启恢复规则以 [PIN_LIFECYCLE.md](PIN_LIFECYCLE.md) 为准；下文仅图片入口、会话级关闭恢复和 Windows 最新历史图片入口的描述已被新规则替代。

## 目标

为 macOS 和 Windows 增加可持久保存、浏览、选择并再次贴出的贴图历史。历史记录覆盖通过普通截图、长截图、OCR/翻译结果原图以及剪贴板创建成功的贴图，并在应用重启后继续存在。同时支持可选的已完成截图自动保存开关。

本次实现保留现有的剪贴板贴图和最近关闭贴图恢复能力，同时明确区分以下概念：

- 最近关闭贴图：当前会话中的撤销栈，用于恢复刚关闭的贴图及其窗口状态。
- 贴图历史：跨会话持久保存的图片档案，用户可以浏览任意记录并重复贴出。
- 截图历史开关：默认关闭的用户配置，开启后成功复制或保存的截图也会进入持久档案。

## 当前实现分析（修复前状态分析）

### macOS（修复前）

- `PinWindowManager.pinClipboardImage()` 只负责从 `NSPasteboard` 读取图片并创建贴图。
- 截图工具在 `ScreenshotCoordinator` 的 `.pin` 分支中直接调用 `PinWindowManager.pin(...)`，长截图也使用同一个管理器。
- `PinHistoryStore` 实际是内存中的关闭贴图撤销栈：
  - 只有贴图窗口关闭后，`windowWillClose` 才会写入快照。
  - 数据仅保存在进程内，退出 Polyglance 后全部丢失。
  - `popMostRecent()` 会消费记录，只支持按关闭顺序逐个恢复。
  - 没有历史列表、缩略图、选择、单项删除或清空界面。
- 名称容易让人误以为已经具备截图历史。该类型承载窗口位置、透明度、锁定状态和 OCR 上下文，适合继续作为会话级关闭恢复栈，不适合直接改造成持久图片档案。

### Windows（修复前）

- 每次创建 `PinWindow` 时，默认会调用 `PinHistoryManager.SavePinToHistory(bitmap)`，PNG 文件保存在 `%APPDATA%\Polyglance\PinHistory`，最多保留 30 张。
- 截图贴图和长截图贴图会经过 `PinWindow`，因此图片实际上已经写入磁盘；剪贴板贴图也会写入同一目录。
- 修复前没有历史浏览界面。`RestoreMostRecentPin()` 只读取最新 PNG，而且不删除或推进记录，所以重复调用会一直贴出同一张图片。
- `PinHistoryManager` 是静态类型，路径和容量写死，异常大多被静默忽略，缺少可注入依赖和单元测试。
- 文件没有稳定的记录标识、来源类型和明确的元数据，现有 `PinHistoryItem.Width/Height` 也没有被填充。

## 结论

修复重点是新增持久档案、降采样缩略图管理和历史浏览窗口，不破坏或替换现有关闭恢复栈。同时修复 DPI 定位、索引容灾、坏文件隔离与失败反馈。

## 设计方案

### 1. 建立独立的持久贴图档案

两端使用一致的数据概念：

```text
PinArchiveItem
  id: UUID/string
  createdAt: timestamp
  pixelWidth: integer
  pixelHeight: integer
  source: screenshot | longScreenshot | clipboard | ocr | translation | legacy
  imageFileName: string
```

接口规范：

```text
list() -> newest-first items
loadThumbnail(id, maxPixelDimension = 480) -> downsampled frozen/cached image
loadImage(id) -> full decoded image
append(image, source) -> item?
delete(id) -> operation result
deleteAll() -> operation result
```

存储与容量规则：

- macOS 使用 `Application Support/Polyglance/PinHistory`。
- Windows 延续 `%APPDATA%\Polyglance\PinHistory`，兼容并导入现有 `pin_*.png` 文件，来源标记为 `legacy`。
- 图片统一保存为 PNG，索引使用 JSON。索引写入采用临时文件加原子替换，避免异常退出造成半写入。
- 默认最多保留 30 条，同时限制总图片大小为 512 MiB。
- 超限清理采用最旧记录清理策略（按创建时间先后顺序删除最早的历史文件，非 LRU 访问命中淘汰），同时同步扣减账面容量与磁盘实际删除。
- 缩略图通过原生解码降采样生成（最长边不超过 480 像素），列表仅读取缩略图，禁止主线程完整解码大图。
- 内存缓存预算设为 32 MiB，窗口隐藏或关闭时释放缩略图缓存。
- 索引损坏时自动备份（最多保留 3 份历史损坏备份），并根据目录内有效 `pin_*.png` 重建索引；损坏或 0 字节图片重命名隔离为 `.corrupted`，不再参与扫描。

### 2. 明确记录时机并防止重复

- 普通截图贴图：贴图窗口创建成功后记录一次，来源为 `screenshot`。
- 长截图贴图：最终拼接图片创建贴图成功后记录一次，来源为 `longScreenshot`。
- 剪贴板贴图：创建成功后记录一次，来源为 `clipboard`。
- OCR 选区和翻译结果贴图：保存用于贴图的原始图片，来源分别为 `ocr` 和 `translation`。
- 从历史窗口再次贴图时设置 `recordInArchive = false`，不得创建新的历史记录。
- 历史图片贴出使用共享的几何定位逻辑，按鼠标所在屏幕的可用区域等比缩放并居中约束，防止跨 DPI 或负坐标副屏下偏移出屏幕。

### 3. 保留 macOS 最近关闭恢复栈

- 保留现有 `PinHistoryStore` 的窗口快照行为和所有相关测试。
- `恢复最近关闭的贴图`（macOS 快捷键 Cmd+Option+V）继续恢复窗口位置、大小、透明度、锁定状态和 OCR 上下文，并保持会话级、后进先出的语义。
- Windows 对应的托盘项文案改为 `贴出最近历史图片`，快捷键由 `HotkeyRestoreMostRecentPin` 配置（默认 Win+Alt+V）。
- 历史浏览窗口本身通过菜单栏/托盘菜单入口打开，不强制占用全局快捷键（原汇报提及的 Cmd+Shift+H 快捷键不属于系统默认配置）。

### 4. 新增双端历史窗口

入口：

- macOS 菜单栏的 `贴图管理` 子菜单新增 `贴图历史…`。
- Windows 托盘菜单的 `贴图管理` 子菜单新增 `贴图历史…`。
- 保留 `贴出剪贴板图片`、隐藏/显示/关闭全部贴图等现有入口。

窗口特性：

- 原生窗口，显示标题、数量和本地存储提示。
- 主区域网格展示缩略图、时间、分辨率和来源标签。
- 存储层串行执行后台读写与缩略图解码，保持记录、删除、清空的操作顺序，支持界面代次取消与内存预算淘汰。
- 单击选中，双击或点击 `贴出` 创建贴图，支持删除选中项和二次确认清空全部。
- 删除、清空与写入失败返回结构化错误并在界面提示，不伪装成功。

### 存储修复补充

- 新图片写入前先恢复索引，避免重建时把新图片导入两次；按 ID 和图片文件名检查重复记录。
- 日期写入保留毫秒精度，同时间的旧记录保持原有插入次序。
- 截图和贴图仍立即显示；PNG 编码、保存和历史读取由后台串行队列执行，正常退出等待待处理写入完成。
- 图片校验实际解码像素，并缓存文件大小、修改时间与校验结果；文件变化后重新校验。
- 隔离图片最多保留 3 项，图片与隔离文件共同受 512 MiB 限制；清空历史会一并删除隔离图片。占用或权限导致删除失败时保留可管理记录并提示。
- 索引首次保存成功后才执行容量清理；清理失败时尝试撤销新记录，撤销也失败则保留记录以便用户处理。
- Windows 多 DPI 几何测试不代表实际多屏界面验证，混合缩放屏幕仍需人工检查。

### 5. 保存已完成截图到历史记录开关

- 两端设置界面新增默认关闭的开关：`保存已完成截图到历史记录`。
- 开关关闭时：仅已贴出的图片进入历史档案，不破坏原有贴图历史行为。
- 开关开启时：用户复制或另存为普通截图、长截图成功后，自动将最终图像写入历史档案。
- 取消保存、复制失败、取消截图或二维码识别不记录。同一次截图事件不重复写入。

### 6. Windows 现有数据迁移与多屏定位

- 首次加载新档案时扫描现有 `pin_*.png`，对未索引的文件创建 `legacy` 记录，创建时间取文件时间，宽高从图片头读取，操作幂等。
- 提取共享定位计算 `PinPositioning`，明确物理像素与 WPF DIP 转换关系，支持 100%、125%、150%、200% 缩放率，负坐标副屏与小副屏几何约束。

## 验收标准

- 用户可以从 macOS 菜单栏或 Windows 托盘菜单打开 `贴图历史…`。
- 退出并重新启动应用后，之前创建的贴图仍显示在历史列表中。
- 列表加载流畅，不阻塞界面线程，内存占用受到 32 MiB 预算限制。
- 索引损坏后能自动备份并从有效文件重建。
- 用户可选择任意历史图片再次贴出，从历史贴出不产生重复记录。
- 双端设置中开关可正常读写与持久化，开启后复制/保存的截图可进入历史。
- 单元测试覆盖缩略图尺寸、多 DPI 几何定位、损坏索引重建、损坏图片隔离与设置持久化。
- 双端完整构建与签名验证通过。
