# 图片和文本贴图生命周期

本次在已有截图历史实现上，参照 PixPin 调整图片、文本贴图的关闭、恢复和销毁行为。本文描述当前实现；旧方案中仅支持图片、Windows 反复贴出最新历史图片等内容已被本次实现替代。

## 使用规则

| 操作 | 行为 |
| --- | --- |
| 贴出剪贴板内容 | 优先读取图片，没有图片时读取纯文本。文本可选择、复制，支持复制可见区域为图片。 |
| 截图后贴图 | 直接使用截图结果，不依赖剪贴板当前内容。 |
| 从历史贴出 | 使用已有历史编号，不重复新增历史图片；文本记录按文本重新打开。 |
| 隐藏 | 只隐藏窗口，保留内容和未关闭状态；重启后重新显示。 |
| 关闭 | 保留历史及窗口状态，可按实际关闭顺序逐个恢复，最近关闭的优先。 |
| 销毁 | 删除对应 PNG、原文和窗口状态，清除关联关闭恢复记录；同一历史编号的其他打开副本也关闭。删除失败会提示，不报告成功。 |
| 销毁全部贴图 | 销毁当前打开贴图对应的内容，不清空其他历史记录。 |
| 清空历史 | 清理全部档案与关联恢复状态，包含隔离的损坏图片；失败项仍需重试。 |
| 正常退出并重启 | 自动恢复未关闭的图片／文本贴图的位置、大小、透明度、锁定和置顶状态。已关闭窗口不会自动弹出。 |

销毁按历史编号关联，不根据像素是否相同判断：两次独立截图产生不同记录，互不影响。关闭恢复列表最多保留 20 个窗口；图片历史仍采用 30 条、图片文件总量 512 MiB 的限制。仍在显示或暂时隐藏的贴图受容量保护；全部历史都受保护时，新内容仍可显示，但保存失败会提示，不能保证这条新内容重启恢复。

文本原文限制为 UTF-8 1 MiB，历史预览为有尺寸上限的 PNG；复制全部文字保留原文，复制可见区域为图片只导出当前显示区域。纯文本不会执行 HTML、脚本或加载外部资源。

## 存储与顺序

- 沿用现有历史目录、PNG 与 `index.json`，增加 `sessions.json` 保存窗口实例编号、历史编号、状态、几何信息和可选原文。
- 创建图片前预留历史编号。PNG 保存、状态保存、删除使用同一串行队列，防止销毁后被延迟保存重新创建。
- 窗口状态每 0.5 秒检查一次，仅变动时写入，关闭和正常退出前再次保存。异常断电可能丢失最后尚未落盘的变动。
- 图片贴图上的标注在关闭、正常退出时合成为 PNG 保存，重启恢复后的标注已经合并到图片，不能继续逐个撤销旧标注。
- 删除历史后，旧窗口的延迟状态更新和图片更新不能重新创建该记录。历史列表中的删除可让当前窗口暂时继续显示，但不会保留其后续恢复状态。
- `sessions.json` 原子替换，不复制含原文的备份。已有状态文件损坏时不静默覆盖，会保留文件供排查；图片历史仍可浏览，窗口状态／原文不承诺从损坏文件自动恢复。
- PNG 索引损坏时从图片文件重建，保留可从文件名识别的历史编号。旧记录没有原文时继续按图片打开。
- 启动时逐张加载，自动恢复的图片像素内存预算为 512 MiB。超出的记录保留在历史中，并提示手动贴出；此预算不是整个应用的内存上限。
- 恢复时检测屏幕位置，原屏幕不再可用时调整到可见位置。Windows 使用 HWND 物理坐标判断屏幕相交；混合 DPI 的实机多屏视觉效果仍需人工验收。

## 范围与注意事项

- 本次涵盖普通截图、长截图、剪贴板图片及纯文本贴图。OCR／翻译专用结果窗口保留原有交互；其结果原图仍进入历史，但不把进行中的识别、翻译任务序列化为重启任务。macOS 专用结果窗口销毁时同步删除对应原图历史。
- 未增加文件、颜色、LaTeX 贴图、HTML 富文本、鼠标穿透等完整 PixPin 功能，也未改变原有快捷键组合。
- 历史在本机保存，不是加密保险箱。销毁是文件系统删除，不承诺安全擦除，也无法删除操作系统备份或用户另外保存的副本。
- macOS 开发版和正式版仍沿用已有历史目录；应避免同时运行并写入同一目录。本次没有增加跨进程文件锁。

## 验证范围

新增存储与原生窗口测试覆盖：原文往返、选择文本、位置／透明度恢复、按关闭顺序恢复、销毁清理、容量保护、关闭恢复条数限制、无效状态拒绝、损坏状态文件保护、PNG 索引重建编号保持，以及删除后的延迟更新拒绝。

交付前运行 macOS Swift 完整测试、Rust 测试及真实 Windows 完整测试，并构建 macOS Dev 应用和 Windows 应用、安装包、便携包。不以自动化测试替代混合 DPI 多屏人工验收。
